## 2. Copy the files over your repo and rebuild

## What changed
**Super admin (/admin)**
- Edit a client: company name and workspace (sign-in) name. Header **Edit** or panel **Edit name or workspace**.
- Delete a client: only when paused; type the workspace name to confirm. Removes people, chats, files and meetings.
- Free up space: remove chat files older than 30 days / 3 months / 6 months / 1 year, or all. Shows what it frees first; messages stay and say the file was removed.
- Selecting a client pre-selects its current plan in "New plan"; applying the same plan again just says it's already on it.
- New table heading: gradient icon tile, client count badge, live "active · paused" line.

- Recording is switched off for every plan and locked in the plan editor. Meeting passes never allow recording. To bring it back later: set `VideoFeatures.RecordingAvailable = true` in `ShankhNaad.ServiceLibrary/Video/VideoProviders.cs` (once a Record button and saving flow exist).

**Welcome email and Forgot password** (needs email set up: `Smtp` settings)
- **Add person → "Email them an invite"** (on by default): they get a welcome email with the workspace name and a link to set their own password (works once, 7 days). No temporary password needed. Turn it off to set one yourself as before.
- **Team → Edit → "Email a set-password link"**: sends someone a link to choose a new password (3 days). Their current password works until they use it.
- **Sign-in page → "Forgot password?"**: emails a 1-hour link. The page says the same thing for any address, so it can't reveal who has an account; at most one link a minute per person.
- Using a link sets the password, clears any lockout, and signs the person out on other devices. Only a hash of each link is stored.

**Team page look**
- Right side: new **Seats** and **Storage** cards. Each shows "used · free · total" under the heading, a gradient gauge with the figure in the middle, and Used / Free / Total tiles. Light and dark themes.

**Fixes (windows)**
- Confirmation and warning boxes opened from inside a window (for example "Email a set-password link" in Edit) now appear above that window instead of behind it. This applies everywhere in the app.

**Team page: who can do what**
- Everyone in the workspace now sees **Team** in the left rail and the list of people (removed people are hidden from members).
- Only **workspace admins** see Add person, Edit, Deactivate, Activate and the Active column; members see a note instead. The server refuses those actions for members too.

**Team: active / inactive**
- Admins can click the **Active** switch in the table (or use **Deactivate** / **Activate** in the top bar). Inactive people are signed out at once and can't sign in; their messages stay and their seat is freed.
- "Remove/Restore" are now called "Deactivate/Activate", and the status "Removed" is now "Inactive". You can't make yourself inactive.

**Team: edit a person**
- Team → select a person → **Edit** (or double-click the row): change name, email, Workspace admin, and optionally set a new temporary password (with a Generate button).
- Changing someone's email, role or password signs them out so they sign in with the new details; a new password also clears a sign-in lockout.
- You can edit yourself too (stays signed in). You can't remove your own admin role, and a workspace can't be left without an admin.

**Meetings**
- Click the period label (e.g. "November 2026") to jump to any month and year.
- Repeat: Once / Weekly / Weekdays / **Pick days** (e.g. Mon, Wed, Fri), with an optional **last day** (up to one year). Live summary counts the meetings. Calendar invites (.ics) follow the same days and end date.

**Table headings (Meetings and Team too)**
- Meeting list / Meetings in this period: count badge + "live · upcoming · ended".
- Team → People: count badge + "online · admins · seats used".
- Shared helper `SN.tableHeading(tableId, count, meta)` in `wwwroot/js/shankhnaad.js`; styles apply to any table it's used on.

**Glass scrollbars**
- Every scrollable area (page, tables, side panels, dropdown lists): slim frosted thumb, no arrow buttons, blue-purple-pink gradient on hover. Light and dark themes. Firefox gets a thin matching bar.

**Call alerts bell** (bottom of the left rail)
- Always visible now and shows the state: blue bell = on, amber crossed bell = blocked, pink dot = not decided yet.
- Click it: asks for permission, or explains how to turn alerts back on (or off), with exact steps for Edge, Chrome or Safari.

**Email sending (MailKit)**
- Email invites now go through MailKit, so port 465 (MilesWeb / Plesk) works as well as 587. Add the NuGet package `MailKit` (already listed in ShankhNaad.ServiceLibrary.csproj; Visual Studio restores it on build).

**Fixes**
- Safari on Mac: frosted-glass blur now also works on Safari 17 and older (added `-webkit-backdrop-filter` to 8 style rules in site.css, shankhnaad.css and modern-input-with-search.css).
- Schedule and Add person windows no longer open by themselves on page load.
- "Last day" date picker was clipped inside the Schedule window.
- Dark theme: date picker previous/next month arrows now light up on hover.

## Toast notifications instead of page banners
- New `wwwroot/js/toast.js`: glass toasts (top-right) with success / error / warning / info colours, icon, title, close button, countdown bar (pauses on hover), optional action button. Loaded in `_Layout` and `_AuthLayout`.
- Toasts sit in the browser's top layer (popover), so they show above open Add/Edit windows and confirmation boxes.
- Server messages are written as `<div hidden data-toast="…" data-toast-kind="success|error|warn">`: Admin and Team success/error, plan-full warning, view-only note, Meeting scheduled (with a "Copy guest link" button), sign-in "password set" message, chat errors.
- Small info/warning pop-ups (Select a row, Already active, Choose a plan, Check the details, That time has passed…) are now toasts. Yes/No confirmations stay as confirmation boxes.
- `site.js` uses the shared toast; styles at the end of `shankhnaad.css` (light and dark).

## Headers
- Chat header: the # / person icon is now a gradient tile with a light sweep, the same as the table headings on other pages.
- Top bar: workspace name (e.g. CloudWheel) bigger, extra-bold gradient with a soft glow; "ShankhNaad workspace" now a bold orange-pink-violet gradient. Workspace name above "Chat" is a bold gradient too. Light and dark themes.

## Smoother page changes (Chat / Meetings / Team / Admin)
- Pages now arrive in three steps: the page frame slides in, then the summary cards rise one by one, and only after that the data appears (table rows one after another, Seats/Storage gauges fill, chat messages rise). Data never animates at the same time as the page swap.
- Page swap is shorter and lighter (0.16 s out, 0.34 s in).
- Background spheres continue from where they were on the last page (they used to jump back to the start on every page) and hold still while a page arrives, so the glass panels don't re-blur every frame.
- The main tabs (Chat, Meetings, Team, Admin) are fetched as soon as the pointer rests on them (speculation rules, prefetch only), so the click has almost nothing to wait for.
- Chart.js (250 KB) and the donut chart script now load only on Meetings, the one page that uses them.
- Respects "reduce motion"; data always shows within 1.2 s even if something goes wrong.

## Left rail: tab highlight glides instead of jumping
- One shared highlight sits behind the active tab (Chat / Meetings / Team). When you switch tabs it glides from the old tab to the new one together with the coloured side bar, while the icons stay still. Before, the old page snapped the highlight on click and the new page drew it again, so it jumped twice.
- Edge/Chrome now show the new page only once it is fully loaded (`<link rel="expect" blocking="render">`), so the highlight, gauges and table are already in place when the change starts.
- Files: `_Layout.cshtml`, `wwwroot/js/shankhnaad.js`, `wwwroot/css/shankhnaad.css`.

## Catching wrong emails (Team → Add person / Edit)
Run `database/13_InvitePending.sql` (after 12). Adds NuGet package **DnsClient** (listed in ShankhNaad.ServiceLibrary.csproj; Visual Studio restores it).
1. **"Did you mean …?" while typing**: near-misses of common domains (gmail, yahoo, outlook, hotmail, icloud, rediffmail, zoho…) and of domains already used in your workspace are suggested under the Email field (gmial.com → gmail.com, "gmail" → gmail.com). One click fixes it.
2. **Mail-server check**: when you stop typing (and again when you press Add / Save) the app checks the domain can receive email (MX record, or A/AAAA as the fallback). If it can't, the invite isn't sent and nothing is saved: "gmial.com can't receive email. Did you mean ravi@gmail.com?". A green "can receive email" line confirms good domains. If the server can't reach DNS, the check is skipped — it never blocks a correct address.
3. **"Invited" status + Resend invite**: anyone who has never signed in shows an amber **Invited** badge (and "N invited" in the table heading). Select them and press **Resend invite** in the top bar: a fresh 7-day welcome email; earlier invite links stop working. Someone still "Invited" after a few days probably has a wrong email: Edit → correct → Resend invite.
- Note: no service can confirm that a mailbox itself exists (ravii@gmail.com vs ravi@gmail.com); the Invited badge is how you spot those.
- Files: `Infrastructure/EmailDomainCheck.cs` (new), `ServiceRegistration.cs`, `ShankhNaad.ServiceLibrary.csproj`, `UserDtos.cs`, `UserService.cs`, `ViewModels.cs`, `TeamController.cs`, `Views/Team/Index.cshtml`, `shankhnaad.css`.
